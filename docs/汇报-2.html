基于医患对话的智能病历生成系统

汇报人：黎高和

汇报时间：2026年4月

项目阶段：ASR转写模块 + Web应用框架（已完成）

研究背景与目标

图2：门诊场景痛点分析

研究背景

  • 门诊医生需边问诊边记录病历，注意力分散
  • 医疗场景对术语准确性要求极高
  • 患者口语化表达，医生专业术语混杂
  • 人工录入效率下降，影响问诊质量

研究目标

  • 将医患录音自动转写为对话文本
  • 从对话中抽取病历核心要素
  • 口语化表达纠正为标准医学术语
  • 生成结构化病历（SOAP格式）

核心问题

  • 提高关键术语的识别率与纠错能力
  • ASR错词到标准医学术语映射
  • 抑制幻觉，减少关键事实遗漏
  • 设计工程可落地的实验方案

调研：国内外研究现状

端到端病历生成

  • SOAP note生成：模块化摘要更稳健
  • MIE、SAFE：医疗对话信息抽取框架
  • EMRModel：对话映射到结构化病历模板
  • 抽取与生成为主，术语纠错讨论不足

医疗ASR与术语纠错

  • ASR-EC Benchmark：大模型纠错效果有限
  • Post-decoder biasing：加权词表增强识别
  • DiCODER：词典检索+拼音相似性+受控解码
  • 低频术语识别是系统成败的前置条件

现有研究的不足

中文门诊录音到标准病历的完整系统研究相对分散，模块之间常分别优化，缺少围绕术语准确性的统一设计。降幻觉研究多面向英文，针对中文门诊口语与录音转写误差的证据约束机制仍不充分。

架构细化：分层架构设计

图1：中文门诊病历生成系统分层架构（输入层·处理层·输出层）

架构层次

  • 输入层：ASR模块、原始文本
  • 处理层：证据选择、术语规范化、结构化生成、验证
  • 输出层：结构化病历

设计原则

  • 事实来源单一：对话文本为唯一事实来源
  • 分层处理：证据选择 → 术语规范化 → 结构化生成 → 验证
  • 受控术语增强：术语规范化作为受控的第二步

系统设计：ASR模块架构

设计模式

  • 工厂模式 + 策略模式
  • ASRBase定义统一接口
  • 具体引擎实现转写逻辑
  • ASRFactory统一管理创建

设计原则

  • 单一职责：每个引擎专注一种模型
  • 开闭原则：扩展无需修改现有代码
  • 依赖倒置：依赖抽象接口

扩展性优势

  • 继承ASRBase实现新引擎
  • 通过Factory注册，修改配置即可切换
  • 便于技术选型验证

为什么这样设计？

ASR技术发展迅速，需要快速切换引擎对比效果。工厂模式使得后续接入Whisper或Qwen3 ASR时，只需实现接口并注册，无需修改业务代码。
